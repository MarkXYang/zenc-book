# 附录 E：MISRA C 合规规则参考

当针对安全关键型嵌入式系统、汽车、航空航天或工业系统时，向 `zc` 传入 `--misra` 可以启用 MISRA C 合规性检查并生成符合 MISRA 规范的 C11 代码。

```sh
zc build --misra main.zc
```

## Zen C 如何强制执行 MISRA C

Zen C 的 `--misra` 模式同时验证 **MISRA C 指令/规则**（规则 1.x 至 22.x 以及指令 4.x）与 **Zen C 专用安全规则**（`rule_zen_1_*`、`rule_zen_2_*`）。在 C 编译开始之前，诊断信息就能准确定位到 Zen C 的源代码行。

## 涵盖的规则类别

Zen C 测试套件（`tests/misra/`）针对以下主要 MISRA C 规则组验证合规性：

| 规则组 | 关注领域 | 检查示例 |
| :--- | :--- | :--- |
| **Dir 4.1 – 4.16** | 设计、运行时故障、头文件规范 | 参数验证、溢出/边界感知、资源限制。 |
| **规则 1.1 – 3.2** | 标准 C 符合性与注释 | 有效的 C11 结构、无嵌套/模糊的注释。 |
| **规则 4.1 – 5.10** | 字符集与标识符唯一性 | 转义序列有效性、区分外部/内部标识符名称。 |
| **规则 6.1 – 7.4** | 位段与字面量 | 有效的位段基类型、八进制/后缀/字符串字面量规则。 |
| **规则 8.1 – 8.14** | 声明、链接属性与 `const`/`restrict` | 显式类型、匹配的原型、单一定义链接。 |
| **规则 9.1 – 9.5** | 初始化 | 仅读取已初始化的变量、完整的数组/结构体初始化器。 |
| **规则 10.1 – 10.8** | 基本类型模型 | 无隐式有符号/无符号或收缩算术转换。 |
| **规则 11.1 – 11.9** | 指针转换 | 无不安全的指针到整数转换、`NULL` 指针规范。 |
| **规则 12.1 – 12.4** | 优先级与求值顺序 | 复杂表达式中的显式圆括号、无副作用二义性。 |
| **规则 13.1 – 13.6** | 副作用 | 条件内无赋值、`sizeof` 中无副作用。 |
| **规则 14.1 – 14.4** | 控制流与循环 | 循环计数器纪律、`if`/`while` 中的布尔条件。 |
| **规则 15.1 – 15.7** | `goto`、`break`、`return` 与 `else` | 结构化退出、单一职责分支、`if ... else if ... else` 完整收尾。 |
| **规则 16.1 – 16.7** | `switch` / `match` 语句 | 穷尽分支与显式终止。 |
| **规则 17.1 – 17.8** | 函数与递归 | 检查非 void 返回值（规则 17.7）、避免无界递归（规则 17.2）。 |
| **规则 18.1 – 18.8** | 指针与数组 | 边界安全的指针算术、避免变长数组 VLA（规则 18.8）。 |
| **规则 19.1 – 19.2** | 重叠存储与 `union` | 避免不安全的 `union` 类型双关（type punning）。 |
| **规则 20.1 – 20.14** | 预处理器指令 | include 位置、宏规范（`#define` / `#undef` 纪律）。 |
| **规则 21.1 – 21.12** | 标准库限制 | 标记禁用的 C 运行时函数（例如在严格模式下禁用 `atoi`、`malloc`，禁用 `<setjmp.h>`）。 |
| **规则 22.1 – 22.6** | 资源管理 | 确保打开的资源（`FILE*`、动态句柄）被正确释放。 |

## `--misra` 构建的实用建议

1. **始终检查返回值**（规则 17.7）：对返回 `Result<T, E>` 或状态码的函数结果进行赋值或显式处理。
2. **在有符号、无符号或不同位宽的整数类型之间转换时使用显式类型转换**（规则 10.x）。
3. **在安全关键循环中避免递归和动态堆内存分配**（规则 17.2、21.3）；优先使用固定大小数组和 `defer` 清理。
4. **在 CI 流水线中将 `--json` 与 `--misra` 结合使用**，以收集结构化的违规报告。
