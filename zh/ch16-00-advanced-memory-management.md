# 高级内存管理

在[第 4 章](ch04-00-ownership-pointers-cleanup.md)中，我们探索了 Zen C 的基础内存模型：值默认分配在栈上，非 `Copy` 资源类型强制单一所有者的移动语义，`defer` 语句保证退出作用域时的清理，而实现 `Drop` trait 则自动化了确定性的资源获取即初始化（RAII）。对于绝大多数应用程序代码——操作 `String` 缓冲区、扩展 `Vec<T>` 集合或管理文件句柄——这些高级抽象为你提供了内存安全保证，无需手动簿记，也无需承受垃圾回收带来的暂停。

然而，系统编程常常需要深入到高级容器之下，在字节层面上直接掌控数据在 RAM 中如何分配、寻址、对齐和表示：

- **自定义数据结构与 C 互操作**：构建侵入式链表、环形缓冲区、自定义分配器或零拷贝 FFI 包装器，需要使用裸类型指针（`T*`）、类型擦除指针（`void*`）、指针运算（`ptr + offset`）以及来自 `std/mem.zc` 的类型化堆分配原语。
- **高吞吐阶段性分配**：编译器、HTTP 服务器、游戏循环和协议解析器通常会分配数以千计具有相同明确生命周期的相互关联的小对象。逐个释放每个对象会带来额外的分配器元数据开销和缓存未命中延迟；将它们归组到连续的 **Arena**（`std/arena.zc`）中，可将分配转化为 $O(1)$ 的指针推进（pointer bump），并将释放转化为单次 $O(1)$ 的偏移重置。
- **精确二进制布局与硬件对齐**：网络协议、文件头和内存映射硬件寄存器要求精确的字节偏移，不能有编译器插入的填充（使用 `@packed`）或需要亚字节级的标志打包（位域），而 SIMD 向量单元和多核原子计数器则要求严格的 2 的幂次边界对齐（`@align(N)`）。
- **共享内存覆盖与位重新解释**：底层驱动程序、变体载荷以及 IEEE 754 浮点数位操作有时需要通过无标签 `union` 类型让多个字段占据完全相同的内存地址。

## 选择恰当的内存策略

在选用底层原语之前，请先评估你的问题，并优先选择能满足性能与布局约束的最高级抽象：

| 机制 | 典型用例 | 分配成本 | 释放策略 |
| :--- | :--- | :--- | :--- |
| **栈值与 RAII（`Vec<T>`、`String`、`Drop`）** | 日常应用程序状态、动态集合、文件/套接字句柄 | 栈帧（或容器内的均摊堆分配） | 作用域结束时通过 `Drop` 自动清理 |
| **类型化堆原语（`std/mem.zc` 中的 `alloc<T>`、`alloc_n<T>`）** | 自定义容器、动态缓冲区、手动 C 兼容堆结构 | 每次分配开销（`malloc` / `calloc` / `realloc`） | 显式 `dealloc<T>(ptr)`（通常与 `defer` 搭配） |
| **区域 / 线性推进分配器（`std/arena.zc` 中的 `Arena`）** | AST 节点、单次 Web 请求缓冲区、单帧游戏状态、临时查找表 | $O(1)$ 8 字节对齐的指针推进 | $O(1)$ `arena.restore(mark)`、`arena.reset()` 或自动 `Drop` |
| **布局属性（`@packed`、`@align(N)`、位域）** | 网络传输报头、二进制文件格式、MMIO 寄存器、缓存行 / SIMD 对齐 | 与常规 `struct` 相同 | 与常规 `struct` 相同 |
| **无标签联合体（`union`）** | C FFI 联合体、硬件事件载荷、字节/位重新解释（Type Punning） | 等同于最大变体的大小 | 与常规 `struct` 相同（Copy / POD 成员） |

## 本章你将学到什么

1. **[16.1 裸指针与手动内存管理（`T*`、`void*`）](ch16-01-raw-pointers.md)**：如何使用 `alloc<T>` 和 `alloc_n<T>` 分配零初始化的堆内存，如何使用 `realloc_n<T>` 扩容缓冲区，如何进行带比例缩放的指针运算，如何通过 `void*` 和 `u8*` 转换检查裸字节，以及如何使用 `mem_copy<T>`、`mem_zero<T>` 和 `swap<T>` 操作内存块。
2. **[16.2 Arena 与自定义分配器](ch16-02-arenas.md)**：`std/arena.zc` 中的 `Arena` 如何通过 8 字节对齐的线性推进分配、字符串复制（`dup_str`）、作用域检查点（`save` 和 `restore`）以及瞬间重置（`reset`）来消除单个对象的堆开销。
3. **[16.3 结构体布局、填充与对齐（`@packed`、`@align`）](ch16-03-struct-layout.md)**：为什么编译器会插入填充字节以满足 CPU 对齐规则，重排结构体字段如何零成本缩小内存占用，何时使用 `@packed` 消除填充或使用位域打包亚字节标志，以及 `@align(N)` 如何避免伪共享（false sharing）并启用 SIMD 加载。
4. **[16.4 无标签联合体与位操作](ch16-04-unions.md)**：`union` 如何将多个字段覆盖在偏移量 `0` 处，如何检查原始字节和 IEEE 754 浮点数位域，以及如何将无标签 C 风格联合体与 Zen C 安全的带标签 `enum` 和类型（sum types）进行对比。
