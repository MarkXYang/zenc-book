# 第 17 章：并发

现代硬件的扩展主要依赖于增加 CPU 核心数，而非不断提升单核主频。编写能够安全且可预测地驾驭这些核心的软件，涉及两个紧密相关的概念：

- **并发（Concurrency）**：将程序组织为多个独立的任务，这些任务在重叠的时间段内推进（例如处理成千上万个网络连接，或协调生产者与消费者阶段）。
- **并行（Parallelism）**：在不同的物理 CPU 核心上，在完全相同的物理瞬间执行多个计算（例如将一个庞大的数值数组划分到 4 个或 16 个硬件线程上）。

不同于附带沉重的垃圾回收 $M:N$ 运行时（如 Go 或 Java）的托管语言，也不同于在每个函数签名上都需要复杂且具传染性的生命周期/Pin 标注的语言，Zen C 采取了一种实用的系统级方法：

1. **直接的 1:1 OS 线程（`std/thread.zc`）**：每次调用 `Thread::spawn` 都会创建一个原生操作系统线程（`pthread_t`），没有任何隐藏的调度器线程或运行时启动开销。闭包（`fn[=]() { ... }` 和 `fn[&]() { ... }`）通过自动堆分配的闭包跳板（trampoline，`_z_thread_trampoline`）无缝跨越线程边界。
2. **RAII 同步原语（`std/sync.zc`）**：`Mutex`、`RwLock`、`CondVar`、`Once`、`Barrier` 和 `Semaphore` 将原生 POSIX 同步原语封装在干净的 Zen C 结构体中，并通过实现 `Drop` 自动执行清理；同时，C11/GCC 硬件原子内置函数（`__atomic_fetch_add`、`__atomic_load_n` 等）为计数器和状态标志提供了无锁性能。
3. **消息传递通道**：将环形缓冲区或 `Queue<T>` 与 `Mutex` 及 `CondVar` 相结合，允许线程通过带有自动生产者背压和优雅停机功能的有界通道传递工作项来进行通信。
4. **异步工作池（`ThreadPool`）**：组织持久的 OS 工作线程，从带有背压的有界并发队列中消费任务，消除了为每个任务创建新线程的开销，同时在没有复杂运行时调度器的情况下确保了内存使用的可预测性。

## 选择恰当的并发模型

| 并发模式 | 核心原语 | 最适用场景 |
| :--- | :--- | :--- |
| **数据并行 Fork-Join** | `Thread::spawn`、`thread.join()`、互不相交的切片/结构体 | 将 CPU 密集型数组、图像块或批量计算分区到 $N$ 个核心上，计算期间零加锁。 |
| **共享状态同步** | `Mutex`、`RwLock`、`Once`、`Barrier`、`Semaphore`、硬件原子操作 | 保护共享内存缓存、连接注册表、一次性初始化以及高频遥测计数器。 |
| **消息传递与通道** | 有界环形缓冲区 / `Queue<T>` + `Mutex` + `CondVar` | 将生产者线程与消费者工作线程解耦，具备天然的背压与清晰的队列排空机制。 |
| **异步工作池** | `ThreadPool`、`TaskQueue`、`ResultAggregator` | 通过持久工作线程进行高吞吐任务分发，具有内存有界且可预测的 OS 调度特性。 |

## 本章你将学到什么

1. **[17.1 使用线程同时运行代码](ch17-01-threads.md)**：使用 `Thread::spawn` 和 `thread.join()` 创建并汇合原生 OS 线程，Zen C 的闭包跳板如何跨线程传递捕获上下文，避免循环变量捕获竞争，以及构建 4 线程的 fork-join 计算。

3. **[17.3 通过队列进行消息传递](ch17-03-message-passing.md)**：使用环形缓冲区、`Mutex` 和双条件变量（`not_empty` 与 `not_full`）构建有界线程安全 MPMC 工作通道，处理伪唤醒（spurious wakeups），以及在关闭时干净地排空工作池。
4. **[17.4 异步工作池与任务分发](ch17-04-worker-pools.md)**：构建有界的 `ThreadPool` 和 `TaskQueue`，理解 Zen C 为何青睐 1:1 OS 工作池而非 `async`/`await` 状态机，异步分发任务，以及在工作线程之间聚合结果。
