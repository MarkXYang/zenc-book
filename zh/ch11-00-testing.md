# 编写自动化测试与调试

在传统的 C 开发中，自动化测试和源码级调试往往感觉像是从外部拼接到语言上的独立世界。在 C 语言中编写单元测试通常需要选择并引入外部框架（如 Unity、Check、Criterion 或 GoogleTest），在 `CMakeLists.txt` 或 `Makefile` 中维护并行的测试可执行文件目录，并手动编写逐个注册每个测试函数的 `main()` 函数。如果你忘记在运行器数组中注册某个测试函数，该测试就会在毫无提醒的情况下永远不会运行。

Zen C 采用了一种受现代系统级语言启发的“开箱即用”方法，同时对其 C11 编译模型保持 100% 的忠实：

1. **一等 `test` 块**：你可以使用 `test "description" { ... }` 声明直接在 `.zc` 文件中编写测试——无论是在模块文件中与被测代码放在一起，还是在专用的测试文件中。无需外部测试库、头文件或注册宏。
2. **非致命期望与丰富断言**：内置的 `assert` 和 `expect` 语句——配合来自 `std/test.zc` 的辅助函数——允许你使用完整的字符串插值检查不变量（`assert(actual == 42, "Expected 42, got {actual}")`）。更棒的是，插值的失败消息只在检查失败时才会惰性求值。
3. **零样板代码的测试运行器生成**：当 `zc` 编译包含 `test` 块且没有 `fn main()` 的文件时，它会自动合成一个测试运行器（`_z_run_tests()`）和一个 `main()` 入口点，按顺序执行每个测试，隔离每个测试的失败，在每个测试作用域末尾运行 `defer` 和 `Drop` 清理，并以等于失败检查数的非零状态码退出。
4. **使用 GDB、LLDB 和 VS Code 进行源码级调试**：由于 Zen C 会转译为人类可读的 C，并在使用 `-g` 编译时生成 `#line` 预处理器指令，标准 C 调试器（`gdb`、`lldb` 以及 VS Code C/C++ 或 CodeLLDB 扩展）可以直接逐行单步调试你的 `.zc` 源文件，并原生检查结构体、枚举和切片。

## Zen C 测试在底层是如何工作的

下图说明了 `zc` 如何将你的 `test` 块和断言转换为独立的、零依赖的 C 测试二进制文件：

```
┌──────────────────────────────────────────────────────────────────────┐
│                         rect.zc (源文件)                             │
│                                                                      │
│   struct Rectangle { width: int, height: int }                       │
│   impl Rectangle { ... }                                             │
│                                                                      │
│   test "area calculation" {                                          │
│       let r = Rectangle::new(10, 5);                                 │
│       assert(r.area() == 50, "Expected 50, got {r.area()}");         │
│   }                                                                  │
└──────────────────────────────────┬───────────────────────────────────┘
                                   │
                                   ▼  zc run rect.zc
┌──────────────────────────────────────────────────────────────────────┐
│                     生成的 C11 (转译器)                              │
│                                                                      │
│   1. 自动导入 `std/test.zc` (`expect_eq`, `expect_ne`, ...)          │
│   2. 为每个 `test "..."` 块生成 `static int _z_test_0()`             │
│   3. 生成 `int _z_run_tests()` 运行所有测试并报告摘要                │
│   4. 如果不存在用户定义的 `fn main()`，则生成：                      │
│        int main() { return _z_run_tests(); }                         │
└──────────────────────────────────┬───────────────────────────────────┘
                                   │
                                   ▼  后端 C 编译器 (gcc / clang)
┌──────────────────────────────────────────────────────────────────────┐
│                        测试执行输出                                  │
│                                                                      │
│     TEST: area calculation ... OK                                    │
│                                                                      │
│   0 test(s) failed   (Exit code: 0)                                  │
└──────────────────────────────────────────────────────────────────────┘
```

## 本章路线图

在本章中，我们将从头开始掌握 Zen C 程序的测试和调试：

- **[11.1 如何编写测试](ch11-01-writing-tests.md)**：编写 `test "name" { ... }` 块、使用 `assert` 和 `expect` 检查不变量、使用字符串插值格式化失败诊断信息、使用 `std/test.zc` 比较辅助函数（`expect_eq`、`expect_ne`、`expect_approx_eq`），以及使用 `defer` 和 `Drop` 验证资源清理。
- **[11.2 使用 zc 运行测试](ch11-02-running-tests.md)**：使用 `zc run` 运行独立测试套件和模块内单元测试、理解 `zc` 如何合成 `main()` 与手动调用 `_z_run_tests()` 的区别、使用 `@cfg(...)` 过滤特定平台的测试，以及将 Zen C 测试套件集成到 Makefile 和 CI 流水线中。
- **[11.3 使用 GDB、LLDB 和 VS Code 进行调试](ch11-03-debugging.md)**：使用 `-g -ggdb -O0` 编译以获取源码级 `#line` 映射和 DWARF 符号、在 `.zc` 文件和方法上设置断点、在 `gdb` 和 `lldb` 中检查 Zen C 结构体、带标签联合体和切片、使用 `--emit-c` 保留生成的 `.c` 文件，以及在 VS Code 中配置一键式可视化调试。
